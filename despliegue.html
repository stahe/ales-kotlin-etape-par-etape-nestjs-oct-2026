    12. Despliegue

    Durante el desarrollo, [Android Studio] (o [gradlew installDebug]) instala la versión “debug” de la aplicación: firmada con una clave de depuración generada automáticamente, que habilita el depurador. Para desplegarla, se compila la versión “release”.

    12.1. La versión de producción de la aplicación

    1. Compile la aplicación, especificando la dirección del servidor de producción. En una ventana de símbolo del sistema abierta en la carpeta [rdvmedecins_kotlin]:
    1
    gradlew assembleRelease -Pserver=https://rdvmedecins.example.com

    [Gradle] compila el código [Kotlin] a “bytecode” y luego a código [Dalvik] (el formato de los archivos [.dex], ejecutados por la máquina virtual de [Android], [ART]), y empaqueta todo —junto con los recursos y las bibliotecas— en un archivo APK: el formato de instalación de las aplicaciones [Android]. A diferencia de [Flutter], no hay ningún motor que incorporar: la interfaz la renderiza [Compose], una biblioteca como cualquier otra. El archivo resultante, [app/build/outputs/apk/release/app-release-unsigned.apk], pesa unos pocos megabytes.

    El bloque [buildTypes { release [ ... ] }] de [app/build.gradle.kts] configura esta versión. Allí se puede habilitar el optimizador [R8] ([optimization [ enable = true ]]): elimina el código no utilizado de las bibliotecas y acorta los nombres, lo que reduce el tamaño del APK. Luego hay que indicarle que conserve lo que el serializador encuentra mediante reflexión (las reglas de [kotlinx.serialization] se proporcionan con la biblioteca) y PROBAR la versión optimizada.

    1. Fírmela. [Android] solo instala aplicaciones FIRMADAS. La forma más sencilla es usar [Android Studio]: el menú [Build / Generate Signed App Bundle or APK] crea la clave de desarrollador (un archivo “keystore” protegido con contraseña que debe guardar en un lugar seguro: todas las actualizaciones de la aplicación deben firmarse con ella), y luego compila y firma el APK. También puede definir la firma en [app/build.gradle.kts] (bloque [signingConfigs]) leyendo las contraseñas de las propiedades de [Gradle] en lugar de escribirlas directamente en el código.

    2. Instálela. Con el teléfono conectado a la computadora (cable USB, depuración por USB habilitada):

    1
    adb install app-release.apk

    También puede copiar el archivo APK al teléfono y abrirlo: [Android] le pedirá entonces que permita la instalación de aplicaciones “de orígenes desconocidos”.

    1. Para la publicación real:

    2. [Google Play Store] exige un “Android App Bundle” en lugar de un APK: [gradlew bundleRelease], o el mismo menú de [Android Studio]. Google genera los archivos APK adaptados a cada teléfono;

    3. el nombre y el ícono de la aplicación se configuran en [res/values/strings.xml] ([app_name]) y en [res/mipmap-*/] (menú [New / Image Asset] de [Android Studio]);
    4. [versionCode] (un entero) debe incrementarse con cada publicación; [versionName] es la versión que se muestra;
    5. el servidor debe configurarse con HTTPS (se transmiten contraseñas) y se elimina del manifiesto la línea [android:usesCleartextTraffic="true"];
    6. el token se almacena en [SharedPreferences], un archivo privado de la aplicación. Para mayor seguridad, se puede cifrar mediante el “keystore” de [Android] (biblioteca [androidx.security]).

    12.2. El servidor de producción

    En un entorno de producción real, no olvide el archivo [.env] del servidor:

    • un [JWT_SECRET] largo y aleatorio;
    • un [CAPTCHA_TEST] vacío;
    • [COOKIE_SECURE=true] si el sitio se sirve mediante HTTPS (debe ser así). El cliente móvil envía la cookie independientemente de esta opción: es el navegador quien la aplica;
    • [TRUST_PROXY=true] si el servidor se encuentra detrás de un proxy ([nginx]...), de modo que el límite de intentos vea la dirección IP real de los clientes.

    Luego se inicia el servidor compilado: [npm run build], seguido de [npm run start:prod].
